If your checkout or signup form sends people to a page like `/thank-you`, you can count conversions without code: create a GA4 event from views of that page and mark it as a key event. It's a good start, but it can't see revenue, and reloads or bookmarked visits count again.

## Create the event

<Steps>
<Step>

In GA4, open Admin → Data display → **Events** → **Create event** → **Create**.

</Step>
<Step>

Name it `purchase` for sales, or `sign_up` for signups.

</Step>
<Step>

Add two conditions:

- `event_name` **equals** `page_view`
- `page_location` **contains** `/thank-you`

</Step>
<Step>

Choose **Create**, then mark the new event as a key event (Events → **Mark as key event**).

</Step>
</Steps>

GA4 creates the event for visits from now on, not for past ones.

## Make the page only reachable after paying

- Use a page address nobody links to, like `/thank-you` or `/welcome`.
- Set it to `noindex` so it doesn't show up in Google search.
- If you use Stripe Payment Links or Checkout, set the redirect after payment to this page. [How](/guides/track-purchases-ga4#after-a-stripe-payment-link).

## The limits

|            | Thank-you page             | A real purchase event           |
| ---------- | -------------------------- | ------------------------------- |
| Needs code | No                         | Yes                             |
| Revenue    | No                         | Yes (`value`, `currency`)       |
| Reloads    | Count again                | Ignored with a `transaction_id` |
| Past data  | From the day you create it | From the day you send it        |

When you can, move to a [purchase event](/guides/track-purchases-ga4).

<InSimpleDash>
  With Pro, SimpleDash doesn't even need the GA4 event: in your site's settings, choose **Views of a
  page** under "What counts as a sale?" and type `/thank-you`. Sales by source then counts views of
  that page, back through your GA4 history.
</InSimpleDash>
